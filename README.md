# 입법로그 (Legislative Log)

> 누가 말했는지가 아니라, 무엇이 실제로 바뀌는지를 본다.

대한민국의 주요 법안과 정책을 원문, 데이터, 논리, 실제 결과를 기준으로
추적하는 독립적인 정책 검증 플랫폼입니다. 특정 정당이나 정치인을 지지·공격하지
않고, "그래서 실제로 무엇이 바뀌는가?"라는 질문에 집중합니다.

## 기술 스택

- [Next.js](https://nextjs.org) 15 (App Router) + TypeScript
- Tailwind CSS
- 콘텐츠는 데이터베이스 없이 `src/data/bills/*.ts`에 타입 안전한 구조로 저장됩니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
npm run lint
```

## 구조

```
src/
  app/                 라우트 (홈, 소개, 법안 목록/상세, 정정 기록)
  app/globals.css      디자인 토큰(라이트/다크)과 한국어 타이포그래피 기본값
  components/          UI 컴포넌트 (주장 배지, 비교표, 예측/결과 타임라인 등)
  data/bills/          법안·정책 콘텐츠 (타입: Bill)
  data/corrections.ts  공개 정정 기록
  lib/bills.ts         데이터 조회 헬퍼
  lib/sections.ts      법안 상세 10단계 섹션 정의 (본문과 목차가 함께 참조)
  types/bill.ts        핵심 데이터 모델과 화면 표기용 라벨·설명
```

## UI 규칙

- **색은 전부 CSS 변수**입니다. `globals.css`의 `:root`/`.dark`에 RGB 채널값만
  두고, `tailwind.config.ts`가 `rgb(var(--x) / <alpha-value>)`로 참조합니다.
  덕분에 클래스는 그대로 두고 라이트/다크 테마만 갈아끼울 수 있습니다.
  새 색을 추가할 때는 반드시 두 테마 모두에 정의하세요.
- **본문 글자는 16px 아래로 내리지 않습니다.** 보조 라벨도 11px이 하한입니다.
  모든 글자·배경 조합은 두 테마 모두에서 대비 4.5:1(큰 글자 3:1)을 넘겨야
  합니다.
- **입체감은 테마마다 다르게 만듭니다.** 밝은 화면에서는 그림자로, 어두운
  화면에서는 카드 윗변의 옅은 하이라이트(`--edge`)로 층을 만듭니다. 검은
  그림자는 어두운 배경에서 보이지 않기 때문입니다.
- **제목은 `clamp()` 단계를 씁니다.** `text-display` / `text-title` /
  `text-heading` 세 가지로, 375px과 1440px 사이에서 끊김 없이 자랍니다.
  브레이크포인트마다 크기를 따로 지정하지 마세요.
- **숫자에는 `.num`을 씁니다.** 날짜·수치를 고정폭으로 정렬해 자릿수가
  흔들리지 않게 합니다. 다만 **한글이 섞인 문자열 전체에 걸면 안 됩니다.**
  `<span className="num">{date}</span> 갱신`처럼 숫자만 감싸세요.
- **한국어 가독성**: `word-break: keep-all`로 어절 중간에서 줄이 끊기지 않게
  하고, 본문에는 넉넉한 행간(`leading-ko`)을 씁니다.
- **움직임은 상태가 바뀌는 곳에만** 씁니다. 목차 펼침, 호버, 읽기 진행바가
  전부입니다. 스크롤에 맞춰 카드가 떠오르는 연출은 넣지 않습니다. 화면 밖
  요소를 잠시 투명하게 만들어, 긴 문서 아래쪽에서 내용이 안 보이는 채로 남는
  일이 실제로 생기기 때문입니다.
- **표식은 색만으로 구분하지 않습니다.** 문장 표식(`ClaimBadge`)과 결과
  판정(`OutcomeTracker`)은 색과 함께 서로 다른 아이콘 모양을 갖습니다.
  흑백으로 인쇄하거나 색을 구분하기 어려워도 읽을 수 있어야 합니다.
- **찬반은 초록/빨강을 쓰지 않습니다.** 초록·빨강은 '옳다/그르다'로 읽히기
  때문에, 추진 측과 반대 측은 가치가 실리지 않은 두 색(`stance-pro`,
  `stance-con`)으로 구분합니다.
- **고정 요소 높이는 상수처럼 다룹니다.** 헤더는 `h-14`(모바일 57px) /
  `sm:h-16`(65px)으로 고정돼 있고, 법안 상세의 모바일 목차 바 위치와 섹션
  `scroll-mt` 값이 이 높이를 기준으로 맞춰져 있습니다. 헤더 높이를 바꾸면
  `TableOfContents`와 `Section`, 그리고 `globals.css`의 `--header-h`
  (앵커 이동 시 제목이 헤더에 가리지 않게 하는 `scroll-padding-top`의 기준)를
  **함께** 조정해야 합니다.
- **헤더는 320px에서도 한 줄이어야 합니다.** 메뉴가 두 줄로 접히면 고정 높이가
  깨지고 그 아래 목차 바·앵커 위치가 전부 어긋납니다. 헤더에 무언가를 더할
  때는 320px에서 가로 스크롤이 생기지 않는지 반드시 확인하세요.
- 화면에 보이는 문구는 되도록 쉬운 말로 씁니다. 단계 제목처럼 여러 곳에서
  쓰이는 문구는 `lib/sections.ts`에, 표식·상태 설명은 `types/bill.ts`에
  모아 두어 페이지마다 표현이 어긋나지 않게 합니다.

## 데이터 모델의 핵심 아이디어

- **`ClaimType`**: 모든 문장은 `사실 / 공식 주장 / 해석 / 전망 / 미확인 의혹`
  중 하나로 표시됩니다. (핵심원칙 3)
- **법안 분석 10단계**: 30초 요약 → 현재 vs 변경 후 → 추진 측 주장 → 반대 측
  주장 → 실제 작동 구조 → 수혜자·비용 부담자 → 근거와 불확실성 → 입법로그
  분석 → 예측 기록 → 결과 추적. `src/types/bill.ts`의 `Bill` 타입이 이 구조를
  그대로 강제합니다.
- **예측 기록/결과 추적**: `predictions[]`에 시점·주체·전망을 그대로 남기고,
  `outcomeTracking[]`에서 6개월·1년·3년 시점마다 실제 데이터로 검증합니다.
  아직 검증할 수 없는 항목은 추측으로 채우지 않고 `추적예정` 또는
  `판단보류` 상태로 정직하게 남겨둡니다.
- **정정 기록**: `src/data/corrections.ts`에 중요한 정정 사항을 기록합니다.
  (핵심원칙 7)

새 법안·정책을 추가하려면 `src/data/bills/`에 `Bill` 타입을 따르는 파일을
만들고 `src/data/bills/index.ts`의 배열에 등록하면 됩니다.
